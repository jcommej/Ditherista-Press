# CLAUDE.md — Ditherista, screen-printing fork

Fork of [robertkist/ditherista](https://github.com/robertkist/ditherista) (Qt 6 / C++20 GUI over the
`libdither` C library, MIT) turned into a tool for preparing **screen-printing films**: physical print size,
output DPI, LPI screens with per-ink angles, tone controls, CMYK/RGB separation, lossless 1-bit film export,
PSD with spot channels, presets.

Read this before editing. It exists so a new session — on any PC — does not re-derive the architecture,
re-open decisions already made with the user, or fall into the traps below.

The user (Jacques, screen printer) writes in **French**; reply in French. Code, comments, commit messages
and the app's UI strings are **English**, like upstream.

## 1. Getting started on a new machine (Windows)

```powershell
git clone --recursive https://github.com/jcommej/ditherista
cd ditherista
git remote add upstream https://github.com/robertkist/ditherista
git config --local user.name jcommej
git config --local user.email 227481831+jcommej@users.noreply.github.com   # never the personal address
.\scripts\setup-toolchain.ps1      # Qt 6.9.3 MinGW + qtimageformats + MinGW 13.1 into C:\Qt (aqtinstall, no Qt account)
.\scripts\build.ps1 -Tests         # libdither, the app (dist\ditherista\ditherista.exe), then the unit tests
```

Work happens on `feature/screenprinting-workflow` (see §6), not `main`.

## 2. Commands

| Command | What it does |
| --- | --- |
| `.\scripts\build.ps1` | builds libdither if missing, then the app → `dist\ditherista\ditherista.exe` |
| `.\scripts\build.ps1 -Tests` | same, then `tests\run_tests.ps1` |

## 3. Traps — read first

- **CRLF.** The repo stores CRLF. `sed -i` and naive Python rewrites turn whole files into LF and the diff
  rewrites every line. Edit with the Edit tool, or byte-level scripts that keep `\r\n`.
- **Scripted edits: write the script to a file.** The Bash tool rewrites `\\n` inside inline heredocs, which
  put real line breaks inside C++ string literals twice. Write the Python script with the Write tool, then run it.
- **`application_en_US.ts`** is regenerated by every build. Never commit it (`build.ps1` restores it).
- **Git's `sh.exe` on PATH breaks the Makefiles** (`SET PATH=… &&` recipes need cmd). `build.ps1` strips it.
- **A running `ditherista.exe` locks the file**: the compile succeeds, the final copy into `dist` fails.
  Never kill the user's instance; copy the build under another name if a screenshot is needed.
- **QtTest output is not visible from PowerShell hosts**: `tests\main.cpp` writes `results_<Class>.txt`, which
  `run_tests.ps1` prints.
- **`runDitherThread()` calls `processEvents()` while a ditherer runs.** Anything event-driven (timers, queued
  calls) can re-enter. `applyOutputSize()` refuses while `isDithering`; a resample mid-dither once freed the
  image being written. `reDither()` also returns while `applyingPreset`.
- **The ditherer list reacts to `itemPressed`, not to `currentItemChanged`**: selecting an item in code does
  nothing unless `treeWidgetItemChangedSlot(item, 0)` is called (or `itemPressed` emitted).
- **libdither is an upstream submodule: put new code in the app**, not in `libdither/`.
- **`GraphicsView` has a private member called `scene`** that hides `QGraphicsView::scene()`; go through the base.
- **Ordered dithers put one dark pixel in 64 on pure white** (smallest Bayer threshold lands exactly on 0.5).
  Separated films are cleaned (`cleanExtremes`); the composite keeps upstream behaviour for now.

### Testing the real app without touching the user's keyboard
Add a temporary harness to `main.cpp` (a `QTimer` chain that finds widgets with `findChildren`, emits
`itemPressed`, and `QMetaObject::invokeMethod`s slots such as `outputDpiEditedSlot`, `savePresetNamed`,
`loadPresetNamed`; make `saveFile` a slot temporarily), run the app with a picture argument, `w.grab()` to PNG,
then **remove the harness before committing** (`grep HARNESS` must find nothing). For crashes, build a copy with
`qmake CONFIG+=release CONFIG+=force_debug_info` in a separate folder and run it under
`C:\Qt\Tools\mingw1310_64\bin\gdb.exe -batch -ex run -ex bt`. Independent PSD check: `psd-tools` in a venv.

## 4. Architecture

Upstream structure, kept: `MainWindow` is split across `mainwindow_*.cpp`; `ImageHashMono` / `ImageHashColor`
hold the source, its adjusted version and one cached dithered result per algorithm; `GraphicsView` shows them.

### Pipeline (the physical size is the reference throughout)

```
file ──► adoptNativeImage ── print size = pixels / file DPI (editable, padlock), Output DPI starts at file DPI
          │
          ▼ resample to print size × DPI   (preview: capped at 16 MP — see "Preview and film")
       working image ──► ImageHash*::adjustSource
                           denoise + blur (cached, blur in mm) → gamma/contrast/brightness(/saturation)
                           → tone curve (blacks, shadows, midtones, highlights, whites)
          │
          ├─ Composite ──► mono or colour ditherer ──────────────────────────► film
          └─ Separation ─► CMYK/RGB coverage planes ─► mono ditherer per ink ─► one film per ink
                              (LPI: stretched + rotated matrix; else dot size: coarse grid)
                                                    │
                                    save: PNG / TIFF / BMP (1-bit when b/w) / PSD, DPI in the file
```

### New modules (plain C++, no MainWindow, unit-tested)

| File | Owns |
| --- | --- |
| `screening/screengeometry.h` | DPI / LPI / dot size maths, `pixelsFor`, `previewDpiFor`, the preview and export pixel caps |
| `screening/matrixstretch.*` | one ordered-matrix tile per LPI cell, fractional period, optional rotation (angle) |
| `screening/cellresample.*` | coarse grid for "dot size" (average down in linear light, replicate back) |
| `screening/separation.*` | CMYK/RGB coverage planes, hand-off to mono ditherers, film cleaning, simulated print |
| `adjust/tonecurve.*` | 5-point monotone curve (Fritsch-Carlson) for blacks → whites |
| `adjust/filters.*` | Gaussian blur, guided-filter denoise (multithreaded, float planes) |
| `export/filmwriter.*` | `toFilmImage` (1-bit when possible), TIFF writer (exact DPI rational, PackBits), PNG, BMP |
| `export/psdwriter.*` | PSD: flat composite + spot channels, RLE, resolution resource |
| `presets/presetstore.*` | JSON preset files in `%APPDATA%/ditherista/presets` |

### MainWindow additions

| File | Owns |
| --- | --- |
| `mainwindow_screen.cpp` | Screen panel: print size + padlock, Output DPI, LPI, dot size; `applyOutputSize`, `applyLpi` |
| `mainwindow_tone.cpp` | the 7 extra rows of Input Image Settings (mono page, then colour page) |
| `mainwindow_separation.cpp` | Color Separation panel, per-ink table, rendering/saving films; the settings scroll area |
| `mainwindow_presets.cpp` | Presets bar, `capturePreset` / `applyPreset` |
| `mainwindow.cpp` | `ditherMonoInto` / `ditherColorInto` (dither any cache: preview or film), `renderFilm`, `saveFile` |
| `viewport/graphicsview.cpp` | hold click / Space to show the original, scene item replacement without leaks |

`monoTarget` / `colorTarget` + `renderDpi` let the upstream ditherer functions render either the preview caches
or a short-lived full-resolution cache for export, without duplicating them.

## 5. Decisions already made with the user — do not reopen without them

- **LPI = the period of the screen cell, in physical units.** 45 LPI = 0.564 mm at any DPI; DPI only sets how
  many pixels draw it (6.67 px at 300, 26.67 at 1200). One ordered-matrix tile is stretched over one cell,
  fractional period, no drift. The first version (DPI/LPI = size of one dither pixel) was wrong and was
  replaced. The user once computed 5.31 px for 300/45 (confusing 45 LPI with 0.45 mm); 6.67 is right.
- **LPI only for matrix (ordered) ditherers**; error diffusion, DBS, Riemersma, blue noise get **Dot size in mm**.
- **Changing the DPI never changes the size on film.** Picture is resampled; on load DPI = file DPI (neutral).
- **Neutral settings must reproduce upstream bit for bit** (tests check it). Every new control defaults to 0/off.
- **Preview/export split**: films > 16 MP preview at reduced DPI, export re-renders at full DPI (cap 250 MP).
- **Separation lives in the Mono tab** (each ink is a mono film); CMYK uses maximum black generation.
- **Lossless only**: never JPEG in the film workflow. BMP was asked back (it is lossless). TIFF written by hand
  for an exact DPI rational and true 1-bit.
- **No zip, no release on GitHub for now**; test builds are zipped locally (`dist\ditherista` + a LISEZMOI).
- Known open question: matrix smoothing for round dots / more grey levels at high DPI was proposed and
  postponed by the user ("je valide pour le moment").
